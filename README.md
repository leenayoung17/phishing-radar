# 피싱 탐지 레이더 (Phishing Radar)

의심스러운 **문자·메신저 메시지와 링크**를 붙여 넣으면, 피싱 위험 신호와 판단 근거, 지금 해야 할 대응 방법을 알려 주는 한국어 웹 서비스입니다.

- 서비스 주소: <https://phishing-radar-omega.vercel.app>
- 저장소: <https://github.com/leenayoung17/phishing-radar>
- 성격: 비영리 프로젝트 · **판단을 돕는 참고용 서비스** (피싱 여부를 단정하지는 않아요)

---

## 한눈에 보기

| | |
|---|---|
| **문제** | 스미싱·메신저 피싱은 일상적인 말투로 와서, 일반 사용자가 그 자리에서 판단하기 어렵습니다. |
| **해결** | 받은 문자나 대화 내용을 붙여 넣으면 위험 신호와 근거를 짚어 주고, **무엇을 해야 하는지**까지 알려 줍니다. |
| **특징** | 링크가 없어도 분석 · 대화 내용과 스팸까지 유형별로 판별 · 위험 판정에서 끝나지 않고 대응 방법 안내 |
| **개인정보** | 분석한 내용은 저장하지 않고, 제보 원문은 동의한 경우에만 가려서 저장합니다. |
| **AI 활용** | 머신러닝 통계 모델(위험 참고 신호) · 이미지 생성 AI(로고·마스코트) · AI 코딩 도구(개발) → [15번](#15-ai-활용) |

| **써 보기** | <https://phishing-radar-omega.vercel.app> |

## 1. 만든 이유

스미싱(문자 피싱)과 메신저 피싱은 "엄마 나 폰 고장났어", "택배 주소를 확인하세요"처럼 일상적인 말투로 오기 때문에, 일반 스마트폰 사용자가 그 자리에서 판단하기 어렵습니다. 이 서비스는 **피해를 입기 전에** 메시지를 한 번 붙여 넣어 보고, 왜 의심스러운지와 어떻게 대응해야 하는지 쉬운 말로 확인할 수 있게 돕는 것을 목표로 합니다.

### 이 서비스의 차별점

1. **대화 내용까지 판별합니다.** 링크만 검사하는 방식이 아니라, 문자와 메신저 대화의 **문장 자체**에서 위험 신호를 찾습니다. (예: "엄마 나 폰 고장났어, 상품권 사서 번호 보내줘" 같은 가족 사칭 대화)
2. **링크가 있든 없든 판별합니다.** 링크가 없어도 문장만으로 위험 신호를 찾습니다. 링크가 있으면 주소의 모양(단축 URL, 의심스러운 도메인, 공식 도메인을 흉내 낸 주소 등)도 함께 분석해 판단 근거에 더하고, 위험한 문장에 의심스러운 링크까지 함께 있으면 등급이 올라갑니다. 문장 없이 **링크만 있어도** 주소 구조가 의심스러우면 "주의" 이상으로 판별하고, 주소에서도 의심스러운 점이 없을 때만 "판단 어려움"으로 알려 줍니다.
3. **스팸과 스미싱을 종류별로 구분합니다.** "스미싱·피싱 의심", "불법·광고성 스팸", "스팸이나 스미싱일 수 있음"으로 나누고, 가족 사칭·금전 요구·기관 사칭·인증번호 요구·원격 앱 설치·불법 도박 같은 **위험 유형**도 함께 보여 줍니다.
4. **위험하다고만 말하지 않고 대응 방법을 알려 줍니다.** 위험 유형별 행동 안내와, 이미 링크를 눌렀거나 정보를 입력했거나 송금한 경우 **그 단계에 맞는 후속 조치**를 알려 줍니다.

## 2. 주요 기능

### 메시지 분석
- 받은 문자·메신저 내용과 링크를 입력하면 **위험 등급**을 보여 줍니다.

  | 등급 | 의미 |
  |---|---|
  | 높음 | 여러 위험 신호가 함께 나타남 |
  | 주의 | 위험 신호가 있어 확인이 필요함 |
  | 뚜렷한 위험 신호 없음 | 눈에 띄는 신호는 없음(안전하다는 뜻은 아님) |
  | 판단 어려움 | 내용이 너무 짧거나, 약한 신호 하나뿐이거나, 링크만 있는데 주소에서도 의심스러운 점이 없어 판단하기 어려움 |

- **판단 근거를 문장 위에 표시**합니다. 어떤 표현이 왜 위험 신호인지 원문에서 해당 부분을 짚어 줍니다.
- 위험 유형을 나눠서 보여 줍니다: 가족·지인 사칭, 송금·금전 요구, 금융기관·공공기관·기업 사칭, 인증번호·개인정보 요구, 원격제어 앱 설치 유도, 불법 도박·불법 사이트 유도, 탐지를 피하려는 위장 문자, 재촉·협박 표현(보조 신호).
- 메시지를 **스미싱·피싱 의심 / 불법·광고성 스팸 / 스팸이나 스미싱일 수 있음**으로 구분해 알려 줍니다.
- **링크 분석**: 주소 문자열만 보고 단축 URL, 의심스러운 도메인 끝(TLD), 공식 도메인을 흉내 낸 주소, 글자를 가리거나 띄어 쓴 주소 등을 찾아냅니다.
- 정상 안내 문자가 오탐되지 않도록, **정상 맥락**(공식 안내·부정 문맥 등)이 있으면 점수에서 빼고 그 사실도 보여 줍니다.

### 대응 안내
- 분석된 위험 유형에 맞는 **예방 행동 안내**를 보여 줍니다(고정 문구로 만든 안내이며 AI가 생성한 문장이 아닙니다).
- **"이미 어떤 행동을 하셨나요?"** 에서 링크를 눌렀는지, 정보를 입력했는지, 송금했는지 등을 고르면 그 단계에 맞는 후속 조치를 알려 줍니다.
- 신고·상담 전화번호(인터넷진흥원 118, 금융감독원 1332 등)를 안내합니다.

### 예시 문자
- "이런 문자는 조심하세요!"에서 실제 수법을 바탕으로 만든 **가상의 예시**를 보고, 버튼 한 번으로 분석해 볼 수 있습니다. 예시 속 주소는 모두 가짜입니다.

### 사용자 제보
- 로그인 없이 **분석 실패 / 미탐(놓친 피싱) / 오탐(정상을 피싱으로 판단) / 신종 수법**을 제보할 수 있습니다.
- 메시지 **원문은 사용자가 동의한 경우에만** 함께 저장합니다.
- **만든 목적**: 서비스가 발전하면 사용자들이 보내 준 제보를 바탕으로 새로운 유형의 스팸·스미싱을 학습하고, 놓치거나 잘못 판단한 사례를 줄여 가기 위해서입니다. 자세한 계획은 [11번](#11-앞으로의-계획)에 있습니다. (지금은 제보를 받아 저장하는 기반을 만든 단계이고, 검토와 재학습은 다음 단계로 이어 갈 예정입니다.)

### 화면
- PC와 모바일 모두에서 쓸 수 있는 반응형 화면이고, 다크 모드를 지원합니다.
- 로딩, 오류, 빈 입력, 결과 등 상황별 화면을 갖추고 있습니다.

## 3. 어떻게 판단하나요? (작동 원리)

분석은 세 가지 신호를 **서로 분리해서** 계산하고, 마지막에 사람이 이해할 수 있는 근거와 함께 보여 줍니다.

1. **규칙 기반 엔진** (`src/lib/analysis/engine.ts`, `rules.ts`)
   - 한국어 사기 문장의 특징을 규칙으로 정리해 두고, 원문에서 일치하는 부분을 찾습니다.
   - 공백·특수문자·전각 문자로 위장한 글자도 정규화해서 찾고, 결과 위치는 항상 **사용자가 넣은 원문 기준**으로 표시합니다.
   - 부정 문맥("~하지 마세요")이나 정상 안내 문맥이 있으면 해당 근거를 점수에서 뺍니다.
   - 같은 입력에는 항상 같은 결과가 나오고, 외부 접속이나 저장, 로그 출력을 하지 않습니다.
2. **링크 구조 분석** (`src/lib/analysis/url.ts`)
   - 링크에 **실제로 접속하지 않습니다.** DNS 조회나 평판 조회도 하지 않고 주소 문자열의 구조만 봅니다.
3. **통계 모델** (`src/lib/analysis/model.ts`)
   - 문자 n-gram TF-IDF + 로지스틱 회귀 모델이며, 서버(API)에서만 계산합니다.
   - 모델 점수는 **피싱 확률이 아닙니다.** 화면에는 참고 단계로만 보여 주고, 모델 신호만으로 등급을 "높음"으로 올리지 않습니다.
   - 학습 데이터에 있던 유형을 알아보는 용도라서, **처음 보는 수법에는 약할 수 있습니다.**

엔진 버전은 `rules-0.3.0`, 모델 버전은 `tfidf-lr-0.2.0`입니다.

## 4. 개인정보와 보안

| 항목 | 처리 방식 |
|---|---|
| 분석 요청의 메시지·링크 | 저장하지 않고, 서버 로그에도 남기지 않습니다. |
| 제보의 메시지 원문 | **동의한 경우에만** 저장합니다(DB 제약으로도 막아 둠). |
| 저장 전 가림 처리 | 주민등록번호·전화번호·카드번호·계좌번호·이메일은 가린 뒤 저장합니다(`maskPersonalInfo`). 완벽하지 않아서 화면에서도 "개인정보를 적지 마세요"라고 안내합니다. |
| 제보 분석 요약 | 글자나 주소 문자열 없이 등급·유형·규칙 이름·링크 특징만 저장합니다. |
| 제보자 구분 | 브라우저가 만든 **익명 번호(UUID)** 를 씁니다. 이름·전화번호·IP와 연결되지 않습니다. |
| 횟수 제한 | 같은 사용자 10분에 5건, 전체 1분에 30건. 사용자 구분값은 IP를 비밀값과 섞은 해시이며 IP 원문은 저장하지 않고, 이 값은 하루가 지나면 지웁니다. |
| DB 접근 권한 | 로그인하지 않은 사용자는 표에 직접 쓰거나 읽을 수 없고, 정해진 DB 함수(`submit_report`)로만 제보할 수 있습니다(RLS 사용). |
| 비밀값 | 키·비밀번호는 환경변수로만 다루고 `.env*` 파일은 Git에 올리지 않습니다. |

## 7. 내 컴퓨터에서 실행하기

필요한 것: Node.js, npm

```powershell
# 1) 패키지 설치
npm install

# 2) 환경변수 파일 만들기: .env.example 을 복사해 .env.local 로 저장하고 값을 채웁니다.

# 3) 개발 서버 실행
npm run dev
```

PowerShell에서 `npm.ps1 실행 제한` 오류가 나면 `npm.cmd`, `npx.cmd`로 바꿔 실행하세요. 실행 후 <http://localhost:3000> 에서 확인합니다.

```powershell
npm run build   # 배포용 빌드 확인
npm run lint    # 코드 검사
```

### 환경변수

| 이름 | 설명 | 공개 여부 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 프로젝트 주소. **`https://프로젝트.supabase.co` 형태**로 넣습니다(뒤에 `/rest/v1` 등을 붙이지 않습니다). | 브라우저에 공개되는 값 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase 공개용(publishable) 키 | 브라우저에 공개되는 값 |
| `REPORT_HASH_SECRET` | 제보 횟수 제한용 사용자 구분값을 만들 때 섞는 비밀값(길고 무작위인 문자열). 없으면 저장은 되지만 서버가 새로 켜질 때마다 값이 바뀌어 횟수 제한이 약해집니다. | **비공개** |

> `.env.example`에는 `REPORT_HASH_SECRET` 항목이 아직 없으니, `.env.local`에 직접 추가해 주세요.

## 8. Supabase 설정

Supabase 대시보드 → **SQL Editor**에서 `supabase/migrations/`의 파일을 **이름 순서대로 한 번씩** 실행합니다.

| 순서 | 파일 | 내용 |
|---|---|---|
| 1 | `20261106120000_create_reports.sql` | 제보 표(`reports`)와 접근 권한 |
| 2 | `20261106130000_report_rate_limit.sql` | 횟수 제한 표(`report_rate`)와 제보 함수 `submit_report` |
| 3 | `20261106140000_report_reporter_id.sql` | 제보자 표(`reporters`)와 익명 번호 연결 |

## 9. 배포 (Vercel)

1. GitHub 저장소를 Vercel 프로젝트에 연결합니다. `main`에 올리면 자동으로 배포됩니다.
2. Vercel → **Settings → Environment Variables**에 위 환경변수 3개를 등록합니다(값에 따옴표나 공백을 넣지 않습니다).
3. 환경변수를 추가하거나 바꾼 뒤에는 **Redeploy** 해야 반영됩니다.

## 10. 개발하면서 겪은 문제

**가장 어려웠던 점은 학습하고 검증할 한국어 스미싱 데이터가 많지 않다는 것이었습니다.** 공개된 데이터가 적고, 그중 일부는 생성형 AI로 만든 문자여서 실제 문자와 다를 수 있습니다.

그래서 **있는 데이터를 최대한 조심스럽게 쓰는 방법**을 택했습니다.

- 비슷한 문장은 같은 묶음으로 보고 학습용과 시험용 한쪽에만 넣었습니다(같은 문장이 양쪽에 들어가 점수가 부풀려지는 것을 막기 위해).
- 시험용 데이터는 **한 번만** 평가하고, 결과를 보고 다시 고치지 않도록 이미 평가 결과가 있으면 평가 스크립트가 실행되지 않게 했습니다.
- 학습 데이터와 매우 비슷한 시험 문장은 따로 표시해서, 점수가 부풀려졌는지 확인할 수 있게 했습니다.
- 통계 모델 하나에만 의존하지 않고, **사람이 읽고 이유를 설명할 수 있는 규칙**을 함께 써서 데이터가 적은 약점을 보완했습니다.
- 데이터의 한계(일부가 AI 생성, 규칙 제작자가 쓴 검증 문장은 점수가 높게 나올 수 있음)를 문서에 그대로 적었습니다.

## 11. 앞으로의 계획

이 서비스가 더 널리 쓰이면, 새로운 스팸·스미싱 수법을 파악해 더 많은 범죄를 예방할 수 있다고 생각합니다. **사용자 제보 기능은 그 첫걸음으로 만들었습니다.**

- 사용자가 **오탐**(정상을 피싱으로 판단), **미탐**(놓친 피싱), **신종 수법**을 제보합니다. 메시지 원문은 동의한 경우에만, 개인정보를 가린 뒤 받습니다.
- 제보 표에는 접수·검토 중·반영·반려 상태 칸이 있어서, 제보를 검토하는 흐름을 이어 붙일 수 있게 만들어 두었습니다.
- 모인 제보를 검토해 규칙을 고치고 모델을 다시 학습하는 것이 목표입니다.

> **현재 단계와 다음 단계**: 지금은 제보를 안전하게 **받아서 저장하는 기반**까지 만들었습니다. 제보를 검토하는 관리자 화면과 재학습은 서비스가 자리를 잡은 뒤 **다음 단계로 구현할 예정**입니다.

## 12. 성능 평가 (시험용 데이터 1회 평가)

> 아래 수치는 2026-11-06에 학습에 쓰지 않은 시험용 데이터로 **딱 한 번** 평가한 결과입니다(규칙 엔진 `rules-0.3.0` + 모델 `tfidf-lr-0.2.0`). 시험용 데이터를 보면서 고치면 점수가 실제보다 높게 나오기 때문에 다시 평가하지 않았고, 그 뒤에 수정한 현재 버전은 따로 측정하지 않았습니다.

**평가 방법**: 학습에 쓰지 않은 시험용 데이터로 평가했습니다. 분석 결과가 **"주의" 이상(높음 또는 주의)** 이면 위험으로 판단했다고 보고, 스팸·스미싱 문자를 잡아낸 비율(재현율)과 정상 문자를 잘못 위험으로 판단한 비율(오탐률)을 쟀습니다. 괄호 안은 95% 신뢰구간입니다.

| 시험용 데이터 | 방식 | 스팸·스미싱을 잡아낸 비율 | 정상을 잘못 잡은 비율 |
|---|---|---|---|
| 데이터 1 (2,513건: 스팸 811 · 정상 1,702) | 규칙만 | 86.9% (79.1~91.7%) | 2.4% (1.5~3.4%) |
| | **규칙 + 모델** | **98.2%** (96.3~99.2%) | **2.9%** (2.0~4.1%) |
| 데이터 2 (6,913건: 스팸 3,996 · 정상 2,917) | 규칙만 | 50.5% (46.8~54.3%) | 10.3% (0~27.6%) |
| | **규칙 + 모델** | **96.4%** (93.7~98.2%) | **10.3%** (0~28.9%) |

**읽는 법과 주의점**
- **데이터 2에서 정상 문자를 잘못 잡은 비율이 약 10%로 높게 나왔는데, 확인해 보니 거의 전부 한 묶음 때문이었습니다.** 데이터 2의 정상 문자 2,917건 중 비슷한 문장 300건이 한 묶음으로 묶여 있고, 이 묶음이 통째로 "주의 이상"으로 판단됐습니다(잘못 잡은 301건 중 300건). 이 묶음을 빼면 2,617건 중 1건뿐입니다.
- **신뢰구간이 0~29%로 넓은 것도 같은 이유입니다.** 신뢰구간은 묶음 단위로 다시 뽑아 계산하는데, 300건짜리 묶음이 뽑히느냐에 따라 값이 크게 달라지기 때문입니다.
- 다만 이는 "그 유형의 정상 문자는 통째로 놓쳤다"는 뜻이기도 해서, 좋은 소식만은 아닙니다. 그 묶음이 어떤 문자인지는 열어 보지 않았습니다. 시험용 데이터를 보고 규칙을 고치면 점수가 부풀려지기 때문입니다.
- 데이터 2는 일부가 AI로 만든 문자라서, 실제 정상 문자에서의 오탐률과는 다를 수 있습니다.
- 데이터 2에서는 규칙만 쓰면 스팸의 절반 정도만 잡았고, 모델을 더하자 크게 올랐습니다. 두 데이터의 문장 성격이 다르다는 뜻이기도 합니다.
- 학습 데이터와 매우 비슷한 시험 문장을 빼고 다시 계산해도 결과는 거의 같았습니다(데이터 1: 97.9% / 3.2%, 데이터 2: 96.4% / 10.4%). 같은 문장이 학습과 시험에 섞여서 점수가 부풀려진 것은 아닌 것으로 보입니다.
- 이 수치는 **공개 데이터 안에서의 결과**입니다. 실제로 사람들이 받는 문자, 특히 처음 보는 수법에서도 같을 것이라는 보장은 없습니다.
- 어떤 등급도 피싱 여부를 확정하지 않습니다.

## 13. 한계와 주의사항

- 이 서비스는 **참고용**입니다. 어떤 결과도 "안전" 또는 "피싱 확정"을 뜻하지 않습니다. 의심되면 문자에 적힌 번호나 링크가 아니라 **공식 앱이나 직접 검색한 대표번호**로 확인하세요.
- **정상 메시지를 피싱으로 잘못 보거나, 실제 피싱을 놓칠 수 있습니다.** 그럴 때는 제보 기능으로 알려 주세요.
- 발신자 인증 정보가 없어서 **실제 발신자가 누구인지는 확인할 수 없습니다.**
- 링크는 주소 문자열만 보고 판단하며, 접속해서 확인하지 않습니다. 단축 URL·의심 도메인·공식 도메인 목록은 불완전하며 검증된 목록이 아닙니다.
- 통계 모델은 학습 데이터에 있던 유형 위주로 알아봅니다. 새로운 수법에는 약할 수 있습니다.
- **성능 수치는 12번의 1회 평가이며, 이후 수정한 현재 버전은 별도로 측정하지 않았습니다.** 지금 서비스의 정확도는 이 수치와 다를 수 있습니다.
- 규칙을 만든 사람이 직접 쓴 검증용 문장(`cases.ts`, `validation-sets.ts`)은 실제 성능보다 좋게 나올 수 있어 동작 확인용으로만 씁니다.

## 15. AI 활용

이 프로젝트에서 AI는 세 군데에 쓰였고, **쓰지 않은 곳도 분명히 구분**했습니다.

| AI 기술 | 쓰인 곳 | 내용 |
|---|---|---|
| 머신러닝 통계 모델 | 메시지의 위험을 알아보는 **참고 신호** | 문자 n-gram(1~3글자 조각) TF-IDF + 로지스틱 회귀. 한국어 스미싱·정상 문자 데이터로 학습했고, 학습한 글자 조각은 103,263개입니다. 학습은 `scripts/`의 파이썬 코드로 하고, 서비스에서는 TypeScript로 같은 계산을 직접 구현해 서버 안에서 돌립니다. |
| 이미지 생성 AI (Stable Diffusion 계열) | 서비스 로고와 마스코트 그림 | 학교(교내)에서 제공한 틸론 GPU에서 생성했습니다. 자세한 내용은 16번을 보세요. |
| AI 코딩 도구 | 개발 전반 | ChatGPT로 개발 요청을 정리하고, Claude Code로 화면·서버·DB 구현, 테스트, GitHub와 Vercel 배포를 진행했습니다. |

**AI를 쓰지 않은 부분**
- **위험 신호 규칙**과 **링크 구조 분석**은 사람이 정한 규칙입니다. 그래서 "왜 위험한지"를 원문 위에 정확히 짚어 줄 수 있습니다.
- **대응 방법 안내**는 AI가 그때그때 만든 문장이 아니라 미리 정해 둔 고정 문구입니다.
- 분석할 때 **ChatGPT 같은 생성형 AI(LLM)나 외부 AI 서비스를 호출하지 않습니다.** 그래서 같은 입력에는 항상 같은 결과가 나오고, 입력한 메시지가 외부 AI 서비스로 전송되지 않습니다.

**AI 모델의 한계**
- 통계 모델의 점수는 피싱 확률이 아니며, 화면에는 참고 단계로만 보여 줍니다. 모델 신호만으로 등급을 "높음"으로 올리지 않습니다.
- 학습 데이터에 있던 유형 위주로 알아보기 때문에 처음 보는 수법에는 약할 수 있습니다.

## 16. 교내 GPU(틸론) 활용 — 이미지 생성

서비스 화면의 캐릭터 그림은 **학교에서 제공한 틸론(Tilon) GPU 환경에서 이미지 생성 모델로 직접 만들었습니다.**

| 그림 | 쓰이는 곳 |
|---|---|
| 서비스 로고 (`public/brand/logo.png`) | 맨 위 헤더와 맨 아래 푸터 |
| 마스코트 (`public/brand/report-mascot.png`) | "이렇게 대응하세요" 칸 제목 옆 |

생성 과정은 [`tools/tilon_icon_generator.ipynb`](tools/tilon_icon_generator.ipynb) 노트북에 그대로 담겨 있습니다. 순서는 이렇습니다.

1. **GPU 확인** 후 이미지 생성에 필요한 패키지(`diffusers` 등)를 설치합니다.
2. **모델 불러오기**: GPU 메모리를 확인해서 12GB 이상이면 SDXL(1024px), 그보다 작으면 가벼운 SD 1.5(512px)를 자동으로 고릅니다. GPU 메모리 크기에 맞춰 알아서 돌아가게 만든 부분입니다.
3. **그림 설명(프롬프트) 작성**: 같은 캐릭터·같은 그림체가 되도록 공통 설명을 붙였습니다. "둥근 로봇 마스코트, 머리에 작은 레이더 안테나, 네이비·파랑 몸"이라는 설정에 상황(돋보기를 든 모습, 걱정하는 모습, 초록 체크 옆 등)만 바꿉니다. 글자·워터마크·사진 느낌은 나오지 않도록 금지 설명(negative prompt)도 넣었습니다.
4. **후보 만들기**: 그림마다 4장씩(고정된 시드 번호, 30단계, 설명 반영 강도 7.0) 만들어 번호를 붙여 보여 줍니다. 마음에 들지 않으면 시드를 바꿔 다시 만듭니다.
5. **고르고 다듬기**: 마음에 드는 번호를 고르면 `rembg`로 배경을 지우고, 가장자리 여백을 맞춘 **1024×1024 투명 PNG**로 저장하고 zip으로 묶습니다.

이렇게 만든 그림 중에서 로고와 마스코트를 서비스에 사용했습니다. 그림 안에는 글자를 넣지 않았고, 옆의 글이 의미를 전달합니다.

분석 중·위험·위험 신호 없음·판단 어려움 결과 화면에는 일부러 **단순한 벡터(SVG) 아이콘**(돋보기, 경고 삼각형, 체크, 물음표)을 썼습니다. 글을 읽기 전에 상태를 바로 알아볼 수 있도록, 캐릭터 그림보다 단순하고 또렷한 모양이 더 낫다고 판단했습니다.

**사용한 환경** (노트북 첫 칸 `nvidia-smi` 출력, 2026-11-06 04:52 기준)

| 항목 | 값 |
|---|---|
| GPU | NVIDIA RTX PRO 6000 (출력에서 이름 끝이 `Blac...`으로 잘려 있어 정확한 모델명은 확인하지 못함) |

## 개발 후기

생성형 AI를 활용해 서비스를 처음부터 끝까지 만들어 본 것은 이번이 처음이었습니다. GPU로 이미지 같은 결과물을 만들어 낼 수 있다는 것도 이번에 처음 알았습니다.

가장 힘들었던 것은 데이터였습니다. 모델 하나를 학습시키는 데에도 많은 데이터가 필요한데, 실제 사례에 가까운 데이터를 구하는 일은 생각보다 훨씬 어렵고 제약도 많았습니다. 그래도 가진 데이터로 최선을 다해 보았고, 힘들었던 만큼 값진 경험이 되었습니다.

만들어 보고 싶은 서비스는 많지만, 그중 하나를 끝까지 구현해 보면서 앞으로 다른 서비스도 만들어 볼 수 있겠다는 자신감이 생겼습니다.

이 서비스가 사기 피해를 조금이라도 막는 데 도움이 되기를 바랍니다. 특히 고령의 부모님을 둔 자녀분들이나 아직 스마트폰이 서툰 분들에게 좋은 영향을 주고 싶습니다.
